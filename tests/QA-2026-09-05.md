# ตรวจบั๊กและข้อเสนอ UX/UI — 5 กันยายน 2569

ตรวจโค้ดปัจจุบันจาก commit 17049cc: สต็อกและนำเข้าไฟล์, BOM ราย FG, แผนหลาย FG, ผังพาเลต, STOCK CARD, การซิงค์ และหน้าจอมือถือ ไม่ใช่การรับรองว่าทุกกรณีปราศจากบั๊ก

## แก้ไขในรอบนี้

1. **BOM นับสต็อกซ้ำเมื่อรหัสซ้ำในสูตร** — รวมปริมาณใช้ของรหัสเดียวกันก่อนคำนวณจำนวน FG สต็อกคงเหลือ และมูลค่า เก็บบรรทัดต้นฉบับไว้ครบ พร้อมข้อความว่ารวมกี่บรรทัด ไม่ลบแถวต้นทางโดยเดาว่าเป็นข้อมูลซ้ำ
   - พบใน FG 21-0007-06 และ 21-0021-04 รวม 4 บรรทัดส่วนเกิน จำนวนแถวคำนวณลดจาก 3,375 เป็น 3,371 รหัสบรรจุภัณฑ์ไม่ซ้ำยัง 1,524 รหัส
   - ตัวอย่างจำลอง: สต็อก 10 ใบ สูตรมีการใช้รหัสเดียวกัน 2 และ 3 ใบ เดิมรองรับ 3 FG หลังแก้รองรับ 2 FG และแผน 3 FG แจ้งขาด 5 ใบ
   - หน่วยที่แปลงรวมไม่ได้ทำให้ผลเป็น “ยังประเมินไม่ได้” ใช้เฉพาะอัตราแปลงที่มีแหล่งอ้างอิง
2. **ยอดขาดเล็กมากแสดงเป็นศูนย์** — ยอดบวกน้อยกว่า 0.001 แสดง `<0.001` แทน 0 ในตาราง BOM/แผน โดยไม่เปลี่ยนจำนวนที่ใช้คำนวณ
3. **ไม่เห็นชัดว่าผล BOM ใช้ข้อมูลสำรอง** — เพิ่มวันที่สต็อกอ้างอิงและสถานะกำลังโหลด/โหลดสำเร็จ/ใช้ข้อมูลสำรองในสรุปและแผน กรณีระบบคืนข้อมูลว่างหรือเชื่อมต่อไม่ได้ไม่ถือว่าโหลดล่าสุดสำเร็จ
4. **ตัวเลขนำเข้าผิดรูปแบบถูกเปลี่ยนเป็น 0** — ปฏิเสธตัวเลขที่อ่านไม่ได้หรือไม่จำกัด พร้อมระบุไฟล์ ชีต และรหัสสินค้า เครื่องหมาย `-` หรือช่องว่างยังใช้กติกาเดิมว่าเป็น 0 จึงควรทบทวนกติกานี้กับรูปแบบไฟล์ต้นทางเพิ่มเติม
5. **เลือกหลายไฟล์ต่างวันแล้วอ้างวันที่ไฟล์แรก** — หยุดนำเข้าหากวันที่รายงานที่อ่านได้จากแต่ละชีตไม่ตรงกัน การตรวจนี้เทียบข้อความวันที่ ยังไม่ใช่ระบบเทียบวันหลายรูปแบบหรือรับรองวันที่ที่ไม่ได้ระบุ
6. **ตารางสต็อกรวมจำนวนต่างหน่วย** — แยกแถวของรหัสเดียวกันเมื่อหน่วยต่างกัน เช่น ใบกับม้วน ยอดมูลค่ารวมและจำนวนรหัสไม่ซ้ำยังคำนวณแยกตามความหมายเดิม
7. **ชื่อสินค้า/หมวดหมู่อาจถูกตีความเป็น HTML** — แปลงข้อความก่อนแสดงในตารางสินค้ามูลค่าสูง ชื่อกราฟและ tooltip รวมถึงรายละเอียด BOM ลดช่องทางแทรก HTML ในจุดที่ตรวจพบ ไม่ใช่การรับรองว่าได้ตรวจ XSS ทุกจุดของระบบแล้ว
8. **ข้อความออฟไลน์ทำให้เข้าใจว่าบันทึกในเครื่องถาวร** — เปลี่ยนข้อความซิงค์ให้ตรงว่าการแก้ไขยังอยู่ชั่วคราวในหน้าที่เปิด และแนะนำส่งออกสำรองก่อนปิดหรือโหลดใหม่

9. **ตัวอักษรขาวบนพื้นอ่อนในโหมดมืด** — ใช้สีน้ำเงินเข้มสำหรับแท็บที่เลือกและสีเขียวเข้มสำหรับหัวสินค้า ช่วยให้อ่านได้ชัดทั้งสองโหมด

## ประเด็นสำคัญที่ยังต้องปรับระบบ

### 1. สิทธิ์แก้ไขพาเลต — เร่งด่วน

SQL ในโครงการยังอนุญาต anon INSERT/UPDATE ของ pallet_slots และ receive_dates ด้วยเงื่อนไข true การทดสอบฐานข้อมูลจำลองยืนยันพฤติกรรมนี้ รอบนี้ไม่ได้เปลี่ยนสิทธิ์ระบบจริงหรือออกแบบบัญชีผู้ใช้ใหม่

ควรเพิ่มการเข้าสู่ระบบ แยกผู้ดู/ผู้แก้/ผู้อนุมัติ และบังคับสิทธิ์ที่ฐานข้อมูล การซ่อนปุ่มหรือเพิ่ม PIN เฉพาะหน้าเว็บไม่แก้ปัญหานี้

### 2. การแก้พาเลตพร้อมกัน — เร่งด่วน

STOCK CARD มีการตรวจเวอร์ชันก่อนบันทึกแล้ว แต่เส้นทางเดิมที่ส่งทั้งรายการพาเลตยังใช้ upsert จึงมีโอกาสเขียนทับงานอีกคน ควรเปลี่ยนทุกการเพิ่ม/เบิก/คืน/นำเข้าเป็นการบันทึกที่ตรวจเวอร์ชันหรือธุรกรรมเดียว พร้อมหน้าจอเปรียบเทียบข้อมูลก่อนลองใหม่

### 3. ยืนยันสูตรที่มีรหัสซ้ำกับผู้ดูแล BOM

ระบบรวมยอดใช้ทุกบรรทัดอย่างระมัดระวัง แต่ยังไม่ทราบว่ารหัสซ้ำใน 2 สูตรเป็นความตั้งใจหรือข้อมูลนำเข้าซ้ำ ควรให้ผู้ดูแลสูตรยืนยัน แล้วแก้ต้นทางพร้อมประวัติผู้แก้และวันที่มีผล

## ข้อเสนอเนื้อหาและ UX/UI ตามลำดับ

1. **ใช้คำให้ตรงความหมาย:** เปลี่ยนข้อความหัว/ท้ายที่ยังใช้ “ความพร้อมผลิต” เป็น “ความพร้อมบรรจุภัณฑ์”; เพิ่มคำอธิบายสั้น ๆ ว่า “FG = สินค้าสำเร็จรูป” และหน่วยตามสูตรจริง; ยอดใช้ตามสูตรกับยอดเบิกควรแยกกันเมื่อมีกติกาปัดตามแพ็ก ห้ามเดาอัตราหรือปัดเองทุกหน่วย
2. **ให้ผลที่ต้องทำต่อเด่นก่อน:** กรองแผนเฉพาะ “ขาด / ต้องตรวจสอบ / ทั้งหมด” และส่งออกพร้อมจำนวน หน่วย FG ที่ใช้ร่วม และวันที่สต็อก ลดการคัดลอกเอง
3. **ลดความยาวหน้าบนมือถือ:** ยุบรายการแบรนด์เป็นส่วนเปิด/ปิด เพิ่มปุ่ม “เพิ่ม FG นี้ในแผน” ใต้ผลค้นหา และมีทางลัดไปแผน ลดการเลื่อนผ่านปุ่มแบรนด์หลายแถว
4. **อ่านตารางด้วยนิ้วได้ง่ายขึ้น:** เพิ่มขนาดปุ่มทดลอง/แก้ไขเป็นอย่างน้อยประมาณ 44px พร้อมยึดคอลัมน์ชื่อสินค้าและรหัสไว้เมื่อเลื่อนตาราง ให้รายละเอียดมูลค่าที่ไม่จำเป็นอยู่ในส่วนขยาย
5. **บันทึกแผนร่าง:** กู้คืนรายการ FG และจำนวนที่กรอกได้ แต่คำนวณกับสต็อกปัจจุบันใหม่ทุกครั้ง แจ้งเมื่อความพร้อมเปลี่ยน ไม่เก็บผลเก่าแล้วเรียกว่าเป็นผลล่าสุด
6. **สถานะซิงค์ใกล้จุดทำงาน:** ทุกหน้าที่ใช้ยอดพาเลตควรแสดงสถานะโหลดและเวลาซิงค์ ไม่แสดง 0 เป็นข้อสรุปว่าพื้นที่ว่างขณะที่ยังโหลดไม่เสร็จ เพิ่มปุ่มลองใหม่และบันทึกรายการแก้ไขที่ยังไม่ส่งสำเร็จ
7. **สีควรสื่อความพอใช้:** สีพื้นสต็อกตามเกณฑ์ 100/1,000 ไม่สัมพันธ์กับสูตรทุกสินค้า ควรเน้น “พอกับจำนวนที่ขอ / ขาดเท่าไร / ไม่ทราบ” และมีข้อความกำกับสี
8. **แยกโครงสร้างโค้ดและลดขนาดหน้า:** หน้าเดียวมีข้อมูลและภาพฝังขนาดใหญ่ ควรแยกไฟล์ภาพ โค้ดคำนวณ และข้อมูล เพื่อให้โหลดมือถือเร็วขึ้นและทดสอบการเปลี่ยนสูตรได้ชัดเจน โดยวัดเวลาโหลดก่อน/หลังจริง

ข้อเสนอเหล่านี้ยังไม่ถือว่าได้ติดตั้งครบในรอบนี้ รายการที่แก้จริงอยู่ในหัวข้อแรก ส่วนการเผยแพร่จะตรวจ GitHub Actions และเนื้อหาเว็บตรงกับไฟล์ที่ทดสอบก่อนสรุปผล
