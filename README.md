# BCL WMS

## เข้าสู่ระบบและจัดการผู้ใช้

เว็บใช้ Supabase Auth โดยมีบัญชี `Admin` เพียงบัญชีเดียว ผู้ดูแลเพิ่มและลบผู้ใช้ย่อยได้จากไอคอนบัญชีมุมขวาบน ผู้ใช้ย่อยเข้าสู่ระบบด้วยชื่อผู้ใช้และรหัสผ่านที่ Admin กำหนด การลบบัญชีจะทำให้เข้าใช้เว็บและฐานข้อมูลไม่ได้อีก บัญชีที่ถูกสร้างนอกหน้าจัดการผู้ใช้จะไม่ได้สิทธิ์เข้าระบบโดยอัตโนมัติ

การติดตั้งต้องสร้างบัญชี Auth ของ Admin ใน Supabase ก่อน จากนั้นรัน `supabase-user-login.sql` และ deploy `supabase/functions/pk-user-access/index.ts` โดยคง service-role key ไว้เฉพาะใน Edge Function เท่านั้น รหัสผ่านไม่อยู่ในไฟล์เว็บหรือ GitHub เว็บที่เผยแพร่แล้วต้องใช้ทั้งการย้ายสิทธิ์ฐานข้อมูลและหน้าเว็บเวอร์ชันนี้ร่วมกัน

ข้อมูลที่ฝังอยู่ในไฟล์ HTML/JavaScript แบบ static ยังอยู่ในไฟล์ที่โฮสต์สาธารณะและไม่ถือเป็นข้อมูลส่วนตัว การป้องกันข้อมูลเหล่านั้นต้องย้ายไปอ่านจาก API ที่ตรวจสิทธิ์ก่อนส่งข้อมูล

## ทัวร์คลังสินค้า 3D ก่อนเข้าหน้าหลัก

เมื่อเปิดเว็บครั้งแรกในแท็บ ระบบจะแสดงทัวร์คลังสินค้า 3D ที่สร้างจากชั้นวาง พาเลต กล่อง และทางเดิน เลื่อนลูกกลิ้งเมาส์ลงเพื่อเดินผ่าน 3 ช่วงแล้วเข้าสู่ Dashboard บนมือถือปัดขึ้น หรือใช้ปุ่ม **เริ่มทัวร์/เดินต่อ** ได้ทุกอุปกรณ์ กด **ข้ามไปหน้าเว็บ** เพื่อเข้าทันที และกด **ทัวร์คลัง 3D** ที่หัวเว็บเพื่อชมอีกครั้ง การรีเฟรชแท็บเดิมจะไม่บังคับดูซ้ำ

ฉากใช้ Three.js ที่เก็บไว้ใน `vendor/three.module.js` พร้อมใบอนุญาต MIT ใน `vendor/three.LICENSE`; ถ้า WebGL ไม่พร้อมจะใช้ภาพพื้นหลังสำรอง และยังเข้าหน้าหลักได้ตามปกติ

แนวทางสี ตัวอักษร ระยะห่าง และคอมโพเนนต์ของเว็บอยู่ใน [DESIGN.md](DESIGN.md) ตามรูปแบบ [google-labs-code/design.md](https://github.com/google-labs-code/design.md) โดยนำแนวทางภาพรวมจาก [Warehouse Inventory Dashboard ของ Beadaptify](https://dribbble.com/shots/26587734-Warehouse-Inventory-Dashboard) มาปรับให้เหมาะกับข้อมูลจริงและงานคลัง BCL การเปลี่ยนหน้าจอใหม่ควรใช้โทเคนและหลักการในไฟล์นี้ร่วมกับ CSS กลางใน `index.html`

## รับเข้าและจัดเก็บพาเลต

เมนู **รับเข้าและจัดเก็บ** มี 3 มุมมอง:

1. **รับสินค้า** — สแกนหรือกรอกรหัสสินค้า ใส่เลขรับเข้า จำนวนทั้งหมด และจำนวนพาเลต ตรวจยอดที่ระบบแบ่งให้แต่ละพาเลต แล้วบันทึกและพิมพ์ **FM-ST-019 ใบกำกับสินค้าและวัตถุดิบ** กระดาษ A4 แนวนอนหนึ่งหน้าต่อหนึ่งพาเลต มีใบกำกับเหมือนกัน 4 ใบในหน้านั้น (เช่น 1/10 ทั้ง 4 ช่อง)
2. **จัดเก็บ** — สแกน QR บนป้ายพาเลต จากนั้นสแกน QR ตำแหน่ง **หรือเลือกโซนและตำแหน่งจากรายการ** ตรวจสินค้า จำนวน และตำแหน่ง แล้วกรอกชื่อผู้จัดเก็บก่อนยืนยัน
3. **รายการล่าสุด** — ดูป้ายที่รอจัดเก็บ/จัดเก็บแล้ว เลือกป้ายที่รอจัดเก็บ หรือพิมพ์ป้ายซ้ำ

การสแกนอย่างเดียวไม่เปลี่ยนยอดคงเหลือ ระบบเพิ่มพาเลตในตำแหน่งเมื่อกด **ยืนยันจัดเก็บพาเลตนี้** เท่านั้น

## สแกน QR/บาร์โค้ดในคลัง

ในเมนูพิมพ์ป้ายตำแหน่งและสินค้า ให้พิมพ์ป้าย QR ตำแหน่งตามโซนและป้าย QR สินค้าจากรหัสสินค้าในสต็อกก่อนใช้งาน จากนั้นสแกนตำแหน่งและสินค้า (ลำดับใดก่อนก็ได้) ด้วยกล้องมือถือหรือเครื่องอ่านที่พิมพ์รหัสแล้วส่ง Enter ระบบเปิดพาเลตและไฮไลต์สินค้าที่พบ หรือเติมรหัสสินค้าในฟอร์มรับเข้าให้ตรวจต่อ การสแกนเพียงอย่างเดียวไม่เปลี่ยนยอด ต้องกรอกจำนวนและเลขเอกสารแล้วยืนยันบันทึกตามขั้นตอนเดิม

รูปแบบป้ายที่ระบบสร้างคือ `PKLOC|โซน|ตำแหน่ง` และ `PKITEM|รหัสสินค้า` รหัสสินค้าหรือบาร์โค้ดเดิมใช้ได้เมื่อมีค่าในข้อมูลสินค้าและตรงทั้งรหัสเท่านั้น รหัสที่ไม่พบหรือกำกวมจะถูกปฏิเสธ การใช้กล้องต้องเปิดเว็บผ่าน HTTPS และอนุญาตกล้องบนอุปกรณ์; หากกล้องไม่พร้อมยังใช้เครื่องอ่านหรือพิมพ์รหัสได้

แดชบอร์ด Stock Inventory และ BOM PK สำหรับเผยแพร่ผ่าน GitHub Pages

การเตรียมข้อมูลพาเลตเพื่อเริ่มใช้ Odoo 19 Community อยู่ใน [docs/ODOO-19-ADOPTION.md](docs/ODOO-19-ADOPTION.md) และตัวแปลง `tools/odoo-pallet-export.mjs`

## Cycle Counts · ตรวจนับตามรอบ

เมนู Cycle Counts ใช้แนวทาง [การตรวจนับตามตำแหน่งของ Odoo 19](https://www.odoo.com/documentation/19.0/applications/inventory_and_mrp/inventory/warehouses_storage/inventory_management/cycle_counts.html): ตั้งความถี่เป็นจำนวนวันแยกตามโซน (ค่า 0 คือไม่ตั้งรอบ) เริ่มตรวจนับครั้งแรกเพื่อกำหนดวันนับถัดไป จากนั้นกรอกผลจริงต่อสินค้าและตำแหน่งพาเลต ระบบเก็บยอดในพาเลต ณ เวลาเริ่มนับเป็นยอดตั้งต้น และแสดงส่วนต่างก่อนบันทึกผล

ร่าง แผน และผลตรวจนับอยู่ใน `localStorage` ของเบราว์เซอร์เครื่องนั้น ไม่ซิงค์กับเครื่องอื่น ส่งออก CSV เพื่อเก็บหลักฐานก่อนล้างข้อมูลเบราว์เซอร์ ชื่อผู้ตรวจนับเป็นชื่อที่กรอกเอง ไม่ได้ยืนยันบัญชี การบันทึกผลตรวจนับไม่ปรับยอดพาเลตหรือ Stock โดยอัตโนมัติ ต้องตรวจสอบและแก้ไขในกระบวนการที่ได้รับอนุญาตแยกต่างหาก

## Scrap Inventory · ตัดจำหน่าย

เมนู Scrap ใช้ลำดับงานจาก [เอกสาร Odoo 19](https://www.odoo.com/documentation/19.0/applications/inventory_and_mrp/inventory/warehouses_storage/inventory_management/scrap_inventory.html): เลือกโซน ตำแหน่ง และสินค้า/Lot ที่มีจำนวนคงเหลือ ระบุจำนวน วันที่ เหตุผล เอกสาร และผู้ทำรายการ แล้วตรวจและยืนยัน ระบบตรวจว่าไม่ตัดเกินยอดคงเหลือ บันทึกด้วย RPC ที่ตรวจเวอร์ชันพาเลต และเก็บรายการ `scraps` ในสินค้าเพื่อแสดงใน STOCK CARD ประวัติ Scrap และ CSV หลังบันทึกสามารถตรวจร่องรอยในประวัติการแก้ไขพาเลตได้

`Inventory Loss / Scrap` ในหน้านี้เป็นปลายทางเสมือนที่บันทึกในประวัติ ไม่ใช่ตำแหน่งพาเลตจริง การยืนยันจะลดเฉพาะยอดพาเลตใน Supabase ไม่ปรับ Stock Snapshot บัญชี หรือการสั่งซื้อทดแทนอัตโนมัติ และไม่เปลี่ยนสถานะตำแหน่งพาเลตเป็นว่าง ผู้ปฏิบัติงานต้องตรวจการนำสินค้าออกและเคลียร์ตำแหน่งแยกต่างหาก

## ปฏิทินนัดหมายร่วมทุกเครื่อง

ปฏิทินอ่านและบันทึกรายการในตาราง `event_calendar` ของ Supabase (migration ที่รันแล้วเก็บไว้ใน `supabase-event-calendar.sql`) เมื่อเปิดหน้าเว็บครั้งแรก ระบบนำรายการเดิมใน `localStorage` ของเครื่องนั้นขึ้นฐานข้อมูลหนึ่งครั้งโดยไม่เขียนทับรายการที่มี ID ซ้ำ เครื่องอื่นจะเห็นกิจกรรมเดียวกันผ่าน Realtime และการรีเฟรชทุก 30 วินาทีเมื่อเปิดหน้าเว็บ รวมถึงเมื่อกลับมาใช้แท็บหรือเปิดปฏิทิน หากฐานข้อมูลติดต่อไม่ได้ รายการแคชจะแสดงเพื่ออ้างอิง แต่ระบบปิดการแก้ไขและไม่สร้างการแจ้งเตือนจากข้อมูลที่อาจเก่า

หลังติดตั้ง `supabase-user-login.sql` ปฏิทินให้เฉพาะบัญชีที่ยังมีสิทธิ์เข้าเว็บอ่านและแก้ไขได้ การแจ้งเตือนในกระดิ่งและ Popup ทำงานเมื่อเปิดเว็บไว้เท่านั้น ไม่ใช่ Push Notification ขณะปิดเว็บ

รายงานเทียบสต็อกกับพาเลตแสดงเวลาบันทึก snapshot ของสต็อกผ่าน RPC ที่อัปเดตแล้วในโปรเจกต์เดิมเมื่อ 16 ก.ย. 2026 (`supabase-stock-snapshot-time.sql` เป็นบันทึกคำสั่งที่รันแล้ว ไม่ต้องรันซ้ำ) หากฐานปลายทางยังไม่มี RPC เวอร์ชันนี้ รายงานจะระบุว่าไม่ทราบเวลาบันทึกสต็อกและไม่ยืนยันผลต่างว่าเกิดจากการขาดสินค้า

## ฐานข้อมูลปัจจุบัน

- ตั้งแต่ 2 กันยายน 2026 พาเลตและ Stock ใช้โปรเจกต์ `zgsxbuckjrplkpvtlbmn` ร่วมกัน แต่แยกตารางและกระบวนการบันทึก
- ย้าย `pallet_slots` และ `receive_dates` ครบถ้วนจากฐานเดิม โดยเก็บฐานเดิมและไฟล์สำรองไว้ ไม่เพิ่มระบบ Log แยก
- โหลดข้อมูลพาเลตแบบแบ่งหน้า รองรับมากกว่า 1,000 แถว
- หลังย้าย ทุกเครื่องต้องรีเฟรชเว็บเวอร์ชันใหม่ ห้ามใช้ HTML ที่ดาวน์โหลดไว้ก่อนย้ายเพื่อบันทึกข้อมูล
- รายละเอียดการย้าย การตรวจสอบ และเงื่อนไขย้อนกลับอยู่ใน `tests/PALLET-MIGRATION.md`; `supabase-pallet.sql` เป็นบันทึก migration ที่รันแล้ว ไม่ต้องรันซ้ำ

## สิ่งที่อัปเดต

- ข้อมูล Stock รองรับไฟล์ `200, 201, 202, 204, 300, 401, 800, 900.txt` โดยไฟล์ `300.txt` จะบันทึกเป็นคลัง `300-S` (Supplier)
- ปุ่ม **Update Stock** รองรับ `.xlsx`, `.xls`, `.csv` และ `.txt` รวมทั้งเลือกหลายไฟล์พร้อมกัน
- การคำนวณและเก็บ snapshot ทำผ่าน Supabase RPC
- หน้า BOM รายงานความพร้อมของบรรจุภัณฑ์เท่านั้น โดยใช้ประเภทส่วนประกอบที่กำหนดไว้ ไม่ใช้เลขนำหน้ารหัสเป็นกฎขณะคำนวณ
- สต็อกใน BOM แสดงหน่วยตามสูตร ถ้าหน่วยต่างกันต้องมีอัตราแปลงและแหล่งอ้างอิง มิฉะนั้น FG จะอยู่ในสถานะ **ยังประเมินไม่ได้**
- กระบวนการ Stock แยกจาก `pallet_slots`, `receive_dates` และผัง Zone โดยสมบูรณ์
- หน้าจัดการสินค้าในตำแหน่งมีปุ่ม **รับคืน** ซึ่งเพิ่มยอดกลับเข้าคงเหลือและบันทึกประวัติ
- เมื่อเปิดงาน **แก้ไข**, **เบิก**, **รับคืน** หรือยืนยันลบ ปุ่มจัดการอื่นในแถวจะซ่อนชั่วคราวจนบันทึกหรือยกเลิก
- ชุดปุ่มจัดการและฟอร์มทั้งสามแบบใช้ขนาด ระยะ มุมโค้ง และสถานะ focus เดียวกัน พร้อมรองรับโหมดสว่าง/มืด

## ตั้งค่า Supabase (ครั้งเดียว)

1. เปิด Supabase Dashboard ของโปรเจกต์เดิม
2. ไปที่ **SQL Editor**
3. รันไฟล์ `supabase-stock.sql`
4. ตั้ง Update PIN โดยรันคำสั่งท้ายไฟล์ SQL หลังแทน `YOUR-PRIVATE-PIN` ด้วย PIN ส่วนตัว
5. เปิด `index.html` แล้วทดสอบปุ่ม **Update Stock**; ระบบจะถาม PIN ก่อนส่งข้อมูล

> หน้าเว็บมี Supabase URL และ publishable key เดิมอยู่แล้ว ไม่ต้องใส่ service-role key หรือ Update PIN ใน GitHub

## เปิด GitHub Pages

1. สร้าง repository ใหม่และอัปโหลดไฟล์ทั้งสามไฟล์ในโฟลเดอร์นี้
2. ไปที่ **Settings → Pages**
3. เลือก **Deploy from a branch**, branch `main`, folder `/ (root)`
4. บันทึก แล้วรอ GitHub แสดง URL ของเว็บไซต์

หน้าเว็บต้องต่ออินเทอร์เน็ตเพื่อโหลด SheetJS, Supabase client และข้อมูล Stock ล่าสุด

## แผนรับเข้าประจำวันจาก Google Drive

แท็บ **แผนรับเข้าประจำวัน** อ่านไฟล์ Excel `แจ้งเรียกเข้าวัตถุดิบ RM-PK 2026.xlsx` จาก Google Drive โดยตรง (read-only) เลือกชีตด้วยชื่อวันที่ `DD.MM` เช่น `17.09` และแสดงรายการตามคอลัมน์ PO, รหัสสินค้า, รายการ, จำนวน, หน่วย, บริษัท และช่วงเวลา ระบบโหลดเมื่อเปิดหน้าเว็บ รีเฟรชทุก 5 นาทีเมื่อแท็บกำลังแสดง และมีปุ่มรีเฟรชด้วยตนเอง คำค้นกรองเฉพาะรายการบนวันที่เลือก หาก Drive เข้าถึงไม่ได้จะแจ้งข้อผิดพลาดและคงข้อมูลที่โหลดสำเร็จล่าสุดไว้บนหน้าเว็บ

การอ่านจากเว็บต้องให้ไฟล์ต้นทางเปิดอ่านด้วยลิงก์ได้ หากย้ายไฟล์ เปลี่ยน ID หรือปิดการแชร์ จะต้องแก้ `SOURCE_ID` ใน `receipt-plan.js` หรือปรับช่องทางข้อมูลก่อนใช้งานต่อ แผนเป็นข้อมูลคาดการณ์ แยกจาก STOCK CARD และไม่เพิ่มยอดรับจริงโดยอัตโนมัติ

หลักการจัดประเภทและการแปลงหน่วยอยู่ใน `tests/BOM-CALCULATION-MODEL.md`; วิธีทดสอบฐานข้อมูลสองบัญชีและข้อจำกัดสิทธิ์ที่พบอยู่ใน `tests/DATABASE-TESTING.md`
